# Timeline & Rendering Specification

## 1. Назначение

Таймлайн — единственный источник истины для порядка и времени показа сцен, шотов, титров и аудио. Монтаж не должен зависеть от порядка файлов в каталоге.

## 2. Временная модель

- Внутреннее представление должно использовать целые кадры при заданном FPS либо целые миллисекунды с однозначным преобразованием в кадры.
- Для видео-проекта FPS задаётся в render profile и не меняется неявно между клипами.
- Для каждого клипа явно указываются start и duration.
- Перекрытия клипов разрешены только при явно заданном переходе или композиции слоёв.
- Округление временных значений должно быть централизовано, а не выполняться независимо каждым модулем.

## 3. Типы дорожек

Минимально предусматриваются:
- video;
- image;
- captions;
- voice;
- music;
- sound_effects.

Конкретная реализация может объединять image/video в одну визуальную дорожку, если сохраняется тип ресурса и его поведение.

## 4. Параметры клипа

Минимальные поля:
- `id`;
- `track_id`;
- `asset_id`;
- `start`;
- `duration`;
- `source_in` и `source_out` для обрезки исходного видео/аудио;
- `transition_in` / `transition_out`;
- `transform` для позиции, масштаба и кадрирования;
- `z_index` или эквивалентный порядок слоёв.

## 5. Изображения и статичные сцены

Для статичных изображений поддерживаются:
- заданная длительность;
- масштабирование и кадрирование под формат кадра;
- позиционирование;
- простые панорамирование/приближение (Ken Burns) как необязательный эффект;
- переходы между сценами.

Эффекты должны быть параметризованы и воспроизводимы.

## 6. GIF

GIF может быть исходным анимированным ресурсом или отдельным экспортным форматом. Renderer должен явно поддерживать анимацию GIF; нельзя полагаться на поведение инструмента, который может использовать только первый кадр.

Если выбранный renderer не обеспечивает надёжную работу с GIF, анимированный GIF предварительно преобразуется в видеофрагмент с сохранением длительности, частоты кадров и прозрачности там, где это поддерживается.

**Ограничение титров:** не более 10 слов на один GIF. Если исходное предложение содержит больше 10 слов, оно разбивается на последовательность GIF/титров. Последовательность должна передавать предложение целиком, без потери слов и смысла. Слова считаются по пробельному разделению после удаления отдельной пунктуации по краям токена; дефисное написание считается одним словом. Точная политика подсчёта может быть уточнена тестами.

## 7. Титры

- Текст хранится отдельно от изображения/видеоресурса.
- У каждого титра есть start, duration, текст, язык и стиль.
- Титры не должны выходить за safe area.
- Для длинного текста выполняется разбиение по смысловым фрагментам и временным интервалам.
- Проверяется максимальное число слов на кадр/GIF, длительность показа и отсутствие наложений, если они не предусмотрены сценарием.

## 8. Аудио

- Голос, музыка и эффекты хранятся на отдельных логических дорожках.
- Уровень громкости, fade-in/fade-out и временные смещения задаются явно.
- Проверяется наличие аудио, клиппинг и длительность относительно видео.
- При отсутствии аудио дорожки результат не должен содержать случайный шум или неинициализированный звук.

## 9. Render profile

Профиль рендеринга задаёт:
- container/format;
- video codec и параметры качества;
- width/height;
- FPS;
- audio codec и sample rate;
- pixel aspect ratio и display aspect ratio;
- правила масштабирования;
- параметры GIF, если выбран GIF export.

Конкретные значения профиля первого релиза будут зафиксированы после тестового прототипа.

## 10. Пострендерная проверка

Проверить:
1. Файл существует и имеет ненулевой размер.
2. Файл полностью декодируется.
3. Фактические параметры соответствуют профилю.
4. Длительность соответствует таймлайну с допустимым отклонением.
5. Нет неожиданных чёрных/пустых интервалов.
6. Все обязательные титры присутствуют и читаемы.
7. Аудио синхронизировано и не обрезано.
8. GIF содержит ожидаемое число кадров/длительность, а не один статичный кадр.

Проверки должны выдавать машиночитаемый отчёт.
